# 終端機裡的地城 (dungeon-in-my-terminal)

一款跑在終端機裡的 roguelike 地城探索遊戲：程序生成地城、回合制方格戰棋、d20 骰子判定、Permadeath。
以 Demeo 為節奏參考 — 每回合「移動 + 一個主要行動」，隊伍最多 4 人，死了就重開一局新的地城。
支援一個人指揮整支隊伍，也支援 2-4 人共用一台電腦輪流玩。

 #######

 #.MrR.#
 ###.###
── 第 3/10 層 ‧ 第 7 回合 ‧ Lv 4 ‧ 金幣 84 ‧ 擊殺 12 ─────────────────────────
▶W 戰士            22/32 │ 戰士 的回合              │ 遊俠 的 射擊 → 巨鼠:
  HP ██████░░ MP ███░░   │ 移動 3/4 主要行動 可用   │   d20=20+5 = 25 vs 13 → 重擊!

## 開始玩

只需要 [uv](https://docs.astral.sh/uv/)。Python 3.12+ 由 uv 自己備妥，你不必先裝；
macOS / Linux 的 `curses` 是內建的，Windows 會自動裝 `windows-curses`。

**一行就開玩** — 不用 clone、不用安裝，玩完什麼都不會留下：

```bash
uvx --from git+https://github.com/rockleona/dungeon-in-my-terminal dungeon
```

**想留著常玩**，裝成系統指令：

```bash
uv tool install git+https://github.com/rockleona/dungeon-in-my-terminal
dungeon
```

之後 `uv tool upgrade dungeon-in-my-terminal` 更新、`uv tool uninstall dungeon-in-my-terminal` 移除。
習慣 pipx 的話，等價指令是 `pipx run --spec git+https://github.com/rockleona/dungeon-in-my-terminal dungeon`。

還沒有發佈到 PyPI，所以上面的指令都直接指向 git。

想重玩同一個地城（回報問題或跟朋友比分數時很有用）：

```bash
dungeon --seed 4242
```

結算畫面會顯示這局的種子碼。建議終端機至少 **80 x 30**，最低需要 72 x 20。

從原始碼跑（開發用）就是 clone 之後 `uv run dungeon`，底下〈開發〉還有更多。

## 操作

| 按鍵 | 作用 |
|---|---|
| `↑ ↓ ← →` / `WASD` | 移動（剩餘移動點數見中間欄） |
| `1` `2` `3` | 使用該職業的技能（每回合限一個主要行動） |
| `i` | 打開道具，數字鍵使用 |
| `Tab` | 讓下一位隊友先行動（尚未行動時才可以） |
| `e` / 空白鍵 | 結束這個角色的回合 |
| `>` | 站在樓梯上時叫出商人，逛完再下一層 |
| `m` | 怪物一覽 — 視線內每隻怪物的生命、護甲、距離、狀態 |
| `g` | 圖例 — 地圖上每個符號與反白顏色的意思 |
| `h` / `?` | 操作說明 — 這張表的完整版，畫面右上角隨時提示 |
| `q` | 放棄這一局 |

`m`、`g`、`h` 只是查看，不花回合也不花行動，按任意鍵關掉。

選目標時：方向鍵移動游標、`Tab` 換目標、`Enter` 確認、`Esc` 取消。範圍技能會即時標出會被波及的格子與單位。

商人畫面：`↑` `↓` 選商品、`Enter` 或直接按數字鍵購買；買的是裝備會再問「給誰穿」，按 `1`-`4` 指定隊員。
逛完按 `e` / `>` / 空白鍵下樓，`Esc` 則是先不下去、回地城再繞繞。

## 畫面

最上面一列是**行動順序**：由左至右就是接下來輪到誰，`▶` 標出現在行動的單位。
怪物跟隊友是排在同一條先攻順序上的，所以這一列常常是交錯的 — 看到自己後面連著兩隻怪，
就是該用 `Tab` 讓隊友插隊的時候。看不到的怪物只顯示 `?`：順序是真的，位置不會洩漏給你。

中間是地城地圖，下半是固定高度、依終端機寬度三等分的面板：

| 左欄 | 中欄 | 右欄 |
|---|---|---|
| 隊伍的 HP / MP、狀態、背包 | 輪到誰、剩餘移動與主要行動、技能清單、骰子 | 戰鬥紀錄 |

中欄的骰子區在你選目標時就先告訴你「**幾點以上命中 ‧ 幾點爆擊**」，確認之後骰子會轉動再定格在實際擲出的點數，下面接命中判定與傷害。敵人擲骰時同樣會演一次，所以怪物怎麼打中你也看得見。

範圍技能一律先預覽再發動：地圖上標出會被波及的格子，中欄列出會打到誰，`Enter` 才真的放出去。
以自身為中心的技能（冰霜新星）也一樣 — 不會按下去就直接消耗魔力。

## 遊玩模式

主選單選 **單人** 或 **多人 Hotseat**。

- **單人**：你指揮整支隊伍，最多挑 4 名角色，`Tab` 可以調整隊友的行動順序。
- **多人 Hotseat**：先選 2-4 人，接著大家輪流挑自己的角色。每人至少一名；如果人數不到 4，可以繼續加角色，多出來的會依序輪流分給各位玩家（例如 2 人玩就是 P1、P2、P1、P2）。

多人模式下，只要輪到不同玩家就會跳出交接畫面，寫明換誰、操作哪個角色，按任意鍵接手。狀態列每一列前面的 `P1`-`P4` 就是該角色的主人。怪物的先攻是跟玩家角色混在同一條順序上的，所以隊友之間的順序不一定連在一起 — 這也是 `Tab` 讓隊友先動的用處。

某位玩家的角色全滅時只有他出局，其他人繼續；全隊覆滅才結束這一局。結算畫面會列出各玩家的擊殺數與生還者。

## 規則

- **檢定**：攻擊擲 `d20 + 屬性修正 + 熟練(2)`，對上目標的護甲值(AC)。**自然 20 必中且傷害骰翻倍，自然 1 必失手**。
- **屬性修正**：`(屬性 − 10) ÷ 2`，四項屬性為力量 / 敏捷 / 智力 / 意志。
- **先攻**：`d20 + 敏捷修正`，所有單位（含怪物）排在同一條順序上，所以遊俠常常能先開火。
- **回合**：移動與主要行動可以任意順序使用，**回合只會在你按 `e` 時結束** — 先出手再走位是常見打法，所以不會替你收掉回合。
- **地城**：10 層，第 5 層與第 10 層是王房 — 哥布林王 葛拉許擋在中途，深淵領主在最底層，打倒他才算通關。王被綁在王座廳裡，不會追進走道。
- **下樓**：每下一層，全隊回復 35% 生命與 60% 魔力。這是最穩定的補給，其餘要靠牧師、寶箱與商人的藥水。
- **Permadeath**：角色死亡不可復活，全隊覆滅該局結束，看完戰績後重新產生一座全新地城。

### 職業

| 職業 | 定位 | HP / MP / AC / 移動 | 技能 |
|---|---|---|---|
| 戰士 | 坦克、近戰主力 | 32 / 6 / 16 / 4 | 揮砍、盾擊（暈眩）、挑釁（拉仇恨） |
| 遊俠 | 遠程輸出 | 24 / 8 / 14 / 5 | 射擊、瞄準射擊（優勢）、雙重射擊 |
| 法師 | 範圍法術 | 18 / 14 / 12 / 4 | 奧術飛彈、火球術（會波及隊友）、冰霜新星 |
| 牧師 | 治療支援 | 26 / 12 / 14 / 4 | 錘擊、治療術、祝福 |

職業可以重複選，四個戰士也是合法隊伍。
每次升級的成長也依職業而異：戰士 +8 HP / +1 MP、遊俠 +5 / +2、法師 +4 / +4、牧師 +6 / +3。

### 怪物

隨深度分三個梯次解鎖，前一梯次會慢慢退場：

| 梯次 | 成員（出沒樓層） |
|---|---|
| 淺層 | 史萊姆 1-4、巨鼠 1-4、哥布林斥候 2-6 |
| 中層 | 哥布林戰士 4-9、骷髏弓手 4-9、哥布林薩滿 4-10 |
| 深層 | 地獄犬 7 起、食人魔 8 起、暗影法師 8 起 |

加上兩隻頭目：第 5 層的**哥布林王 葛拉許**與第 10 層的**深淵領主**。
AI 分三種行為：近戰衝鋒、遠程風箏（被貼身會後退）、輔助（優先治療受傷的同伴）。怪物平時是睡著的，看到隊伍或被打到才會醒。

## 成長與商店

十層走到底，隊伍得跟著變強。兩條線都是**全隊共享**的，免得補師被輸出拉開：

- **經驗值 → 全隊共用等級**。每次擊殺都算進同一個經驗池，升到第 n 級需要 `55 × n`
  — 愈後面愈貴，所以深層那些肥怪不會讓等級一路暴衝。升級時**所有還活著的**成員
  加生命與魔力（各職業成長值不同，戰士長血、法師長魔），每 3 級再加 2 點主屬性
  （戰士力量、遊俠敏捷、法師智力、牧師意志）。**陣亡的隊友不會跟著升級。**

  屬性一次加 2 點是刻意的：加值算法是 `(屬性 - 10) // 2`，加 1 點有一半的機會
  什麼都不會變。升級時右邊的紀錄欄會逐一列出每個人拿到什麼
  （`戰士 HP+8 MP+1 力量+2`），看得到的成長才算成長。
- **金幣 → 商人**。金幣有兩本帳：一本是計分用的一生總額，一本是可以花的錢包，
  兩邊同時入帳、只有錢包會扣 — 所以**在商店花錢不會扣你的分數**，儘管花。
  站在樓梯上按 `>` 就會叫出商人。

商品分武器 / 護甲 / 飾品三個欄位，同一個欄位只穿一件，買新的會換掉舊的（不會疊加）。
效果單純是攻擊擲骰、傷害、護甲三個固定加值，所以戰鬥只讀總和，不會因為你穿什麼而有不同規則。
第 4 層與第 7 層各解鎖一階更好的貨：

| 欄位 | 第 1 階 | 第 2 階（第 4 層起） | 第 3 階（第 7 層起） |
|---|---|---|---|
| 武器 | 銳利短刃 40 | 精鋼長劍 90 | 符文巨刃 160 |
| 護甲 | 皮甲 35 | 鎖子甲 85 | 板甲 150 |
| 飾品 | — | 命中護符 55、蠻力指環 70 | — |

治療藥水 20、魔力藥水 18、炸彈 30，隨時都買得到。

## 專案結構

```
src/dungeon_in_my_terminal/
├── cli.py            進入點與參數
├── core/             遊戲規則 — 完全不依賴 curses，可在無終端機環境測試
│   ├── dice.py       擲骰與 d20 檢定
│   ├── dungeon.py    BSP 地城生成、視線、尋路
│   ├── entity.py     單位、屬性、狀態效果
│   ├── abilities.py  技能的資料型別（所有職業與怪物共用）
│   ├── classes.py    四職業資料表
│   ├── monsters.py   怪物資料表與 AI 型別
│   ├── items.py      消耗品
│   ├── shop.py       樓層之間的商人：商品與定價（純資料）
│   ├── combat.py     命中/傷害結算、怪物 AI
│   └── game.py       一整局的狀態機：樓層、回合、座位歸屬、戰績
└── ui/               curses 介面
    ├── render.py     地圖、狀態列、覆蓋視窗的繪製
    └── app.py        主選單、組隊、遊玩迴圈、選目標、交接、結算
```

`core/` 不 import curses 是刻意的：整局遊戲可以在沒有終端機的情況下跑完，測試才能驗證平衡與流程。

### 加一個新職業

在 `core/classes.py` append 一個 `HeroClass` 到 `CLASSES` 就好 — 選單、行動列與戰鬥都是讀這份註冊表。
只有在需要全新的技能型別時，才要動 `AbilityKind` 與 `combat.resolve`。怪物同理，改 `core/monsters.py` 的 `ROSTER`。

## 開發

```bash
git clone https://github.com/rockleona/dungeon-in-my-terminal
cd dungeon-in-my-terminal
uv run dungeon        # 直接跑
uv run pytest         # 測試
```

測試分成規則單元測試與整局的 headless 試玩（`tests/autoplay.py` 是一個很笨的自動代打，用來確認流程不會卡死，也順便當難度曲線的護欄）。

TUI 沒辦法用讀程式碼的方式驗證，所以還有一個 pty 驅動器，它會跑真正的執行檔並把畫面印成純文字：

```bash
uv run python tools/tui_drive.py --last 3     # 只看最後三張畫面
uv run python tools/tui_drive.py --cols 76    # 檢查窄終端機
```

改任何版面或動畫都該跑一次 — 中文字是兩欄寬，只有這個抓得到對不齊或被裁掉的面板。

### 打包

```bash
uv build      # dist/ 產出 wheel 與 sdist
```

純 Python、沒有編譯步驟，所以 wheel 是 `py3-none-any`，一份到處跑；Windows 需要的 `windows-curses` 靠 `pyproject.toml` 裡的平台標記自動處理。
想驗證打出來的東西真的能裝能跑：

```bash
uv tool install dist/dungeon_in_my_terminal-0.1.0-py3-none-any.whl
```
